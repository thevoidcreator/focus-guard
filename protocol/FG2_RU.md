# FG2: Android-подтверждения и независимое USB-восстановление

Файл UTF-8 JSON: `{"version":2,"token":"<JWS>"}`, до16KiB. Strict JSON:
неизвестные и повторные поля отвергаются. JWS ES256, защищённый заголовок ровно
`{"alg":"ES256","typ":"FG2"}`. Подпись64байта R||S, P-256 SPKI base64url.
FG1-сообщения не принимаются как FG2.

Payload Approval включает: version, action, phoneId, phoneSpki, signerSpki,
requestId, nonce(32случайных байта), phase, digest, day, issued, expires,
policyVersion, policy(nullable), replacement. Все поля обязательны в токене.
Запрос phase=request, digest пустой, подписан phoneSpki. Ответ повторяет все
поля запроса, меняет phase=response, digest=SHA256 точных байтов исходного JWS,
подписан signerSpki. Алгоритмы/кривые кроме ES256/P-256 отвергаются.

Действия доверенного телефона: pair/hour/day/remove/policy.
USB: usb_pair/usb_start_remove/usb_finish_remove/usb_start_replace/usb_finish_replace.
Windows принимает только USB-действия и main-ключ. Доверенное приложение
принимает только свои действия и привязанный phoneSpki. Старый phoneId с новым
phoneSpki не перепривязывается автоматически.

На ограничиваемом телефоне есть только один сохранённый pending-токен.
Для применения проверяются точное равенство ожидаемого ответа, подпись,
версия политики, срок по монотонно-привязанному сетевому времени и устройство.
Потребление ответа и изменение состояния записываются одной AtomicFile до
ослабления DPM. Повторная доставка не добавляет время. Запросы отменяются при
смене дня; TTL не более24ч. Отмена/новый запрос инвалидируют старый ответ.

Первоначальная pair разрешена только до активации либо после подтверждённого
USB-восстановления замены. Стороны сверяют120бит контрольного отпечатка
SHA256("FG2-pair|phoneSpki|guardianSpki") по отдельному голосовому каналу.
Guardian ключ Android Keystore требует системной аутентификации, не экспортируется.
PIN не передаётся в Focus Guard. Выбор Telegram/SMS вместо WhatsApp не реализован.

Для usb_start фиксируется issued принятого начального запроса. Состояние
recoveryAt/recoveryAction нельзя отменить ответом guardian. Для usb_finish
проверяется >=48ч и replacement=строковый recoveryAt, совпадение вида процедуры
и основной флешки. Завершение замены закрывает старый guardian и разрешает новую
pair; лимит продолжает действовать. Удаление запускает checkpointed deprovisioning.

Время: HEAD с запретом кэша и случайным query к HTTPS endpoints Google/Microsoft,
валидный TLS, HTTP2xx без redirect, Date>0, Age<=1, RTT<10с, согласие<=60с.
Более ранняя оценка привязывается к elapsedRealtime текущей загрузки. После reboot
не используется изменяемое локальное время для выдачи новых суток/завершения48ч.
Это доверие к TLS и двум операторам, а не автономное криптографическое доказательство
времени. Неверное системное время может помешать TLS: исправить до активации.
