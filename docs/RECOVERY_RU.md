# Восстановление и снятие

Не активируйте управление на основном телефоне без подтверждённого выхода на его
модели и сборке ОС. clearDeviceOwnerApp — testing-only и deprecated; отсутствие
factory reset в коде не гарантирует поддерживаемое снятие Device Owner у OEM.
Production заблокирован. Универсального пароля/скрытой кнопки нет.

Обычный путь: основной ключ подтверждает начало → телефон накапливает 48 часов
подтверждённого монотонного времени → свежий финальный запрос → тот же ключ
подтверждает → проверяемый workflow ОС. Ожидание не открывает приложения.
«Отменить процедуру» сразу удаляет flow и challenge, новый старт отсчитывается заново.
При policy_change процедура аналогична, применяется подписанный полный snapshot.

Экстренный путь: телефон создаёт emergency challenge, доверенный человек своим
независимым заранее зарегистрированным ключом подтверждает немедленное снятие.
Основной/незарегистрированный ключ отвергается. Если ключей нет — поддерживаемого
быстрого выхода нет, поэтому резервные копии проверяются заранее.

Lab workflow сохраняет этапы и может продолжаться после ошибки:

1. Удалить свои Lock Task packages и завершить закреплённые tasks.
2. Снять только приостановки пакетов, записанные в нашем journal.
3. Очистить назначение нашего HOME; Android возвращает обычный chooser/default.
4. Восстановить свои restrictions/auto-time/allowlist/features из snapshot.
   Снятие ограничения отладки **не включает** USB debugging.
5. Только в lab вызвать testing-only clearDeviceOwnerApp; проверить isDeviceOwnerApp=false.
6. Проверить отсутствие admin и собственных блокировок, затем обозначить COMPLETE.
   Открыть системное подтверждение удаления APK по желанию пользователя.

При ошибке показывается стадия и причина; «Повторить» выполняет незавершённый
идемпотентный шаг. Частично восстановленный аппарат не обозначается успешно снятым.
Повтор после process death читает последний durable checkpoint. При corrupt state
boot handler пытается вернуть закрытую allowlist без пересоздания ключей/flow;
восстановление хранилища в этой ситуации требует отдельного расследования.

Нельзя автоматически вернуть предыдущий пользовательский default launcher API DPM,
если он не был назначен нами: снимается только наше persistent preferred правило,
пользователь проверяет/выбирает обычный HOME. Удалённые пользователем пакеты и их
данные приложение не восстанавливает. Snapshot не включает посторонние ограничения.

Для тестовой debug/testOnly сборки до выключения ADB возможна лабораторная команда:
`adb -s TEST_SERIAL shell dpm remove-active-admin ru.focusguard.android.lab/ru.focusguard.android.AdminReceiver`.
Она не является защищённым production-путём. После запрета отладки рассчитывать
на неё нельзя. Программа не включает ADB автоматически.

Factory reset/recovery/перепрошивка стирают личные данные и не засчитываются как
успешное снятие без потерь. Приложение не вызывает wipeData и не предлагает его
как fallback. Не выполнять такие действия автоматически на реальном устройстве.
