# Windows 11 x64

Распакуйте весь `FocusGuard-Windows-win-x64.zip`, запустите
`FocusGuard.KeyConsole.exe`. Self-contained включает .NET/WindowsDesktop runtime;
системная установка .NET для запуска не нужна. Оставьте native DLL рядом с EXE —
они нужны для веб-камеры. Администратор, драйвер USB, autorun и служба не требуются.
Пакет не подписан Authenticode: перед применением сверить SHA256 и происхождение,
для распространения подпишите своим сертификатом по BUILD_RELEASE_RU.

Разделы: настройка USB; привязка; начало удаления; завершение удаления; изменение
политики; аварийное подтверждение; проверка/резерв. Запрос должен соответствовать
разделу. Сначала проверяется подпись телефона, затем показываются device ID,
действие, flow, request ID, версия политики, fingerprint USB и последствия.
Только после ручного подтверждения и нового ввода пароля выполняется подпись.

Для камеры разрешите доступ Windows к камере desktop apps. Используется камера 0
через DirectShow. Если камеры нет/она занята, импортируйте `.fgreq`. Ответ можно
сканировать встроенным сканером телефона или экспортировать `.fgres`. Протокол
работает офлайн и не требует USB debugging. Истёкший/отменённый ответ создайте заново
на телефоне; часы ПК не продлевают срок и не ускоряют 48 часов.

В LocalAppData/FocusGuard/phones.json находятся только публичные идентичности
телефонов. При изменении публичного ключа для того же installationId клиент
отказывает. На новом ноутбуке без записи в реестре требуется явная ручная сверка
существующей идентичности в общем заголовке телефона; это работает и с запросом
уже активированного телефона. Это не молчаливый TOFU и не замена ключа телефона:
новая запись ПК создаётся только после отдельного подтверждения fingerprints.
Телефон после активации сам не принимает новых USB-ключей без защищённого flow.

Основной USB: «Начать удаление», подтвердить, применить ответ телефоном. Ожидание
проходит на телефоне. После готовности телефон создаёт свежий «Завершить удаление»;
нужен тот же основной ключ. Завершение нельзя подготовить до появления challenge.
Для аварийного раздела нужен зарегистрированный ключ независимого доверенного лица.
Публичное время Windows не является доказательством ожидания.

Для изменения настроек телефон принимает JSON будущего snapshot Policy: zone,
sessionMs, apps (packageId + certificateSha256), mainSpki, emergencySpki. Полный
snapshot входит в подписанный запрос и flow; старый основной ключ подтверждает оба
шага. Увеличение сеанса, исключения и смена ключей не имеют прямой кнопки обхода.

Перед эксплуатацией выполнить ручной USB/Windows чек-лист из TEST_REPORT:
создание без форматирования, неверный пароль, отсутствие/извлечение USB, два носителя,
другой ноутбук, QR обеими камерами, файлы без камеры. Сборка на Linux не подтверждает
эти аппаратные сценарии или реальный запуск WPF.
